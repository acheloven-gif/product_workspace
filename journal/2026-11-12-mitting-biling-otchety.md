# 2026-11-12: разбор митинга (биллинг, платёжки, отчёты)

Источник: ClickUp-док «транскрипт митинга». Участники: Наталья и руководитель проектов.

## Платёжки и биллинг
- Платёжка и биллинг: разные сущности. Биллинг = Funnel Fox payments (мозг подписок: хранит транзакции, продукт, тариф, рекуррентные списания).
- Платёжек сейчас 4: 3 Stripe (свои, на разных юрлицах, под белые приложения) и 1 Adyen (через Funnel Fox, общий аккаунт, подаккаунты под проекты).
- Для новых проектов по умолчанию Adyen. Исключение: 3 приложения, изначально заведённые под Stripe (верификация уже пройдена, ими «греем» Stripe, нужно ~200 транзакций, чтобы не заблокировали).
- Новое приложение в Stripe сложнее: нужна верификация (лендинги, домены, описание продукта) через поставщиков.
- Primer = оркестратор платежей (хранит токены, workflow-схема: prepaid-карты отменяем, дальше по проекту по metadata FF org id выбираем платёжку).

## Что делать при новом проекте
- Сначала завести проект в конструкторе Funnel Fox (Даша), правильно назвать по названию приложения.
- Затем написать в телеграм-беседу Funnel Fox: «подключите биллинг к проекту». Подключают только они. Без этого Даша не может создавать продукты (подписки), а разработчик не может связать приложение с воронкой и оплатой.
- Каждый проект = отдельная организация, две ссылки: прод и сэндбокс.
- Наталью добавят в беседу Funnel Fox и дадут доступ к конструктору. Сейчас есть только Primer и PostHog.
- Для РММ нужно подключить биллинг. FoxIQ: биллинг уже подключён. Пункты чек-листа по платёжкам (в т.ч. сохранение токена, bio) пока делает руководитель.
- Рекомендовано прочитать верхний уровень Primer и открытую документацию Funnel Fox (можно через Claude).

## Пульт (дашборд проектов)
- Руководитель хочет добить: все проекты, тесты, чек-лист, статусы. На этой неделе вряд ли, возможно на следующей.
- Тесты Наталья запускает сама: валидация гипотез, согласование, постановка задач, запуск; ключевые метрики теста выводить в пульт.
- По каждому проекту стремиться к постоянным тестам, продуктовый подход, цель: окупать проект. Идея: если не удерживаем на вебе, рассматривать iOS-приложение.

## Рассылка FoxIQ о новом функционале
- Идея: письмо о новом функционале (памяти) неактивным. Выборка тех, кто не реагировал на прошлые письма, мала.
- Наталья предложила вместо этого слать тем, кто был до появления функционала памяти, а пришедшим после не слать.
- Решение: принять самой, без руководителя, ~10 минут, оценить риски; оба варианта допустимы.
- Наблюдение: если на письма нет отклика, возможно, это не тот рычаг. Открытия писем отслеживаются плохо, переходы в приложение учитываются.

## Загрузка разработчиков
- Следить за загрузкой Коли и Корюна и понимать, когда у них закончатся задачи; держать бэклог, не допускать, чтобы один простаивал, другой был перегружен.
- Расставлять приоритеты: иногда выгодно переключить разработчика на проект, где осталось чуть-чуть до запуска (например, FoxIQ, на полдня-день), прежде чем уходить в многодневное новое приложение, блокирующее FoxIQ.
- FoxIQ: гипотеза 1 на тесте, гипотеза 2 недавно доделана, тоже на тесте, про третью проверить. Продуктовую приёмку Наталья делает.

## Еженедельный отчёт (вместо ежедневного)
- Каждый понедельник, за прошлую неделю, один общий отчёт, в личку руководителю, любой формат (можно вечером). Задача в ClickUp заведена и появилась.
- Состав: по проектам что сделано, блокеры и места, где нужно решение руководителя; основные метрики по приложениям с сравнением с предыдущей неделей (новые подписки, процент отмен, возвращаемость на день N и т.д.); раздел по тестам (что за тест, метрика, результат группы A/B, вывод: раскатываем или пробуем другой подход); гипотезы в бэклоге.
