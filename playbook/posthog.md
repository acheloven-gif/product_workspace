# PostHog для Claude — подключение и правила (для продакта)

> **Как пользоваться:** закинь этот файл в Claude и напиши: «Подключи PostHog по части 1, а части 2–4 сохрани себе как постоянные правила (CLAUDE.md)».

---

## Часть 1. Подключение

PostHog у нас свой (self-hosted, не облако): https://ph.app-inkfolio-reader.pro. Инвайт в PostHog уже пришёл на почту — сначала прими его и зайди.

1. **Создай личный API-ключ:** в PostHog → аватар справа вверху → **Settings → Personal API keys → Create personal API key**.
   - Название: например, `claude-natasha`.
   - Доступ: проект **Azora** (он один на все приложения, см. часть 2).
   - Права: **Read** на всё + **Write** для:
     - Cohort
     - Alert
     - Dashboard
     - Insight
     - Insight variable

     Этого хватает, чтобы Claude читал данные и сам собирал дашборды, графики, когорты и алерты. Удалять и менять чужое он не сможет.
   - Ключ начинается на `phx_`. Скопируй сразу: PostHog покажет его один раз.
2. **Подключи к Claude Code** одной командой в терминале:
   ```
   claude mcp add posthog -- npx -y mcp-remote https://mcp.app-inkfolio-reader.pro/mcp --header "Authorization:Bearer phx_ТВОЙ_КЛЮЧ"
   ```
   В `Authorization:Bearer` **нет пробела после двоеточия**, иначе команда сломается.

   Или вручную в конфиг MCP:
   ```json
   {
     "mcpServers": {
       "posthog": {
         "command": "npx",
         "args": ["-y", "mcp-remote", "https://mcp.app-inkfolio-reader.pro/mcp", "--header", "Authorization:Bearer phx_ТВОЙ_КЛЮЧ"]
       }
     }
   }
   ```
3. **Перезапусти Claude** и проверь, что появились инструменты posthog. Пробный вопрос: «Сколько событий за вчера по каждому project?» — должна прийти таблица с web, foxiq, ridwan, nalumi и т.д.

Ключ личный. Никому не пересылать, не вставлять в общие чаты и задачи. Если ключ засветился — удали его в Personal API keys и создай новый.

## Часть 2. Как устроены данные

### Один проект на все приложения
- В PostHog **один проект на все приложения**. Приложения различаются только свойством события **`project`** (`properties.project`). **В любом запросе первым делом фильтр по `project`**, иначе данные приложений смешаются.
- Значения `project` (на 23.10.2026):

  | project | что это |
  |---|---|
  | `web`, `ios` | Azora: веб-приложение и iOS |
  | `foxiq` | FoxIQ (IQ / тренировка мозга), приложение |
  | `robella` | Robella (стилист), приложение |
  | `ridwan` | Ridwan (ислам), приложение |
  | `nalumi` | Nalumi (косметолог), приложение |
  | `charisly` | Charisly (личностное развитие), приложение — только начали слать события |
  | `lunavel` | Lunavel (форк Azora), приложение |
  | `azora_ff`, `foxiq_ff`, `robella_ff`, `brainza_ff` | **воронки FunnelFox** этих продуктов |

  Мусорные значения `iq`, `funnel` — старые тесты, не брать. Около 12 тыс. событий в месяц приходят **без `project`** — их нельзя отнести ни к одному приложению, в анализ не брать.
  Появилось новое приложение — сначала посмотреть актуальный список значений `project`.
- **Веб и iOS — разные пользователи**, сквозной связки нет.
- **Время в проекте — UTC.** День по Москве = с 21:00 UTC предыдущего дня до 21:00 UTC. В ответах явно писать, по какому времени считали.
- Данные приходят в реальном времени, задержка около секунды.

### Воронки FunnelFox (`*_ff`)
- События воронки: `funnel_start` → `funnel_screen_open` (свойства `screen_id`, `screen_index`) → `funnel_email_submit` → `funnel_checkout_open` → `funnel_purchase_start` → `funnel_purchase_success` / `funnel_purchase_fail` → `funnel_complete`.
  Apple Pay отдельно: `funnel_applepay_open`, `funnel_applepay_authorized`, `funnel_applepay_cancel`.
- **UTM:** `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` — отдельные свойства. Остальные параметры ссылки (`adgroup_id`, `network`, `gclid` и т.п.) лежат только внутри `$current_url`.
- PostHog видит тех, у кого **загрузилась воронка**, а не клики по рекламе. Кликов в рекламном кабинете всегда больше.
- Воронка и приложение — **разные персоны** в PostHog. Связывать человека между воронкой и приложением — по email (`person.properties.email`).

### Приложения
- Общие события у веб-приложений: `login`, `magic_link_requested`, `onboarding_started` / `onboarding_step` / `onboarding_completed`, `first_run_*`, `paywall_shown` / `paywall_closed` / `paywall_plan_selected`, `subscription_started` / `subscription_cancelled` / `subscription_renewed`, `subscription_cancel_click` / `subscription_cancel_confirm`, `in_app_purchase_click` / `in_app_purchase_success`, `settings_open`. Плюс у каждого свои (FoxIQ — `game_*`, `test_*`, `iq_result_shown`, `certificate_*`; Ridwan — `lesson_*`, `quiz_*`, `audio_*`; Nalumi — `scan_*`, `routine_*`, `guide_*`; Robella — `report_opened`, `capsule_*`, `tryon_*`).
  Названия у приложений разные — **сначала посмотреть, какие события есть у нужного `project`**, не угадывать.
- **Ловушка «новые пользователи»:** сервер сам создаёт персону (событие `$set` с библиотекой `posthog-php`), когда человек оставляет email в воронке — даже если он ни разу не открыл приложение. Пример FoxIQ, 22.10: 65 новых персон, из них в приложение зашли только 12. **«Новый пользователь приложения» = у персоны есть события из браузера (`properties.$lib = 'web'`)**, а не просто первая запись.
- Без оплаты человек тоже может попасть в приложение (в FoxIQ видно: смотрят IQ-результат, пейволл). Платящих определять по `subscription_started` / данным оплат, а не по факту входа.

### Тестовые пользователи — исключать
- **Dev-окружение:** у Ridwan, Nalumi, Charisly события с dev приходят с `environment = 'dev'` — исключать.
- **FoxIQ:** email с `+` (`%+%@%`), `%@gox-media.com`, `%@yandex.ru`, `%test%`, а также содержащие `k.k.tarasova`, `nikitos.gura`, `dariaivanova`, `eevakenn`, `nedvedyea`, и адреса `kkk@gmail.com`, `myskillhouse2020@gmail.com`. Данные FoxIQ до ~12.10.2026 — только тесты.
- Тестовые проходы воронок с «пустышками» в метках (`utm_campaign=88888888`) и незаполненными шаблонами (`{campaignid}`).
- **FoxIQ (найдено 29.10):** события воронки `foxiq_ff` приходят в PostHog только с 16.10.2026 — источник покупателей до этой даты не виден. `utm_source` = `4`, `19`, `22` — реклама Meta (в ссылке `fbclid`), `google` — Google Ads. В `subscription_started` свойство `platform` (`ios`/`web`) — похоже, устройство при покупке: все такие покупатели пользуются веб-приложением. `subscription_expired` с `reason = payment_failed` приходит и после отмены пользователем — «отказ банка» считать только без предшествующей `subscription_cancelled`. `first_run_started` срабатывает автоматически на экране результата — не метрика старта тренировки (для этого `game_started`). В `iq_result_shown` есть `iq_score`, `is_test`, `environment`.
- Для остальных приложений полных списков пока нет. Если цифры странные — сначала проверить, нет ли внутренних аккаунтов, и дописать их сюда.

## Часть 3. Как считать и отвечать

### Как считать
- **Всегда писать, что посчитано: люди или события.** Конверсии, воронки, «сколько человек дошли / купили» — уникальные люди (`person_id`). Объём действий («сколько игр сыграно») — события. Если из вопроса непонятно — показать оба числа.
- Под каждым выводом — **период, часовой пояс и размер выборки**.
- Для воронок различать строгий порядок шагов и любой порядок.
- Аномалии сравнивать с прошлой неделей или месяцем, а не смотреть абсолют.
- **Деньги не считать по PostHog.** Выручка, возвраты, чарджбеки — в FunnelFox / Primer / Stripe / Adyen. PostHog — только поведение.
- Ловушки HogQL: `LEFT JOIN` возвращает `0` / `''` / `1970-01-01` вместо `NULL` (`IS NULL` врёт) — использовать флаги вида `1 AS has_x`. Коррелированные подзапросы выполняются некоррелированно — заменять на JOIN.

### Как отвечать
- Разделять: **видно в данных** / **предположение (почему)** / **не знаем (откуда взять)**. Не выдавать догадку за факт.
- По просьбе показывать запрос.
- Если событие или свойство не нашлось — сказать об этом, а не подставлять похожее.

## Часть 4. Как этим пользоваться

### Хороший вопрос = приложение + период + что считаем
- «FoxIQ, вчера по Москве: сколько новых пользователей зашли в приложение, их почты и что они делали».
- «Ridwan, 14–20 окт: сколько уникальных дошли от `login` до `lesson_completed`, по шагам онбординга».
- «Nalumi, последние 7 дней: где уходят на скане — по шагам `scan_*`, люди».
- «foxiq_ff, 16–22 окт: воронка от `funnel_start` до `funnel_purchase_success` по `utm_source`».
- «Какие события вообще есть у charisly?» — полезно перед ТЗ на аналитику нового приложения.

### Для продуктовой работы
- **Перед ТЗ на доработку** — спроси Claude, где реально отваливаются люди и какими фичами пользуются. Цифры клади в ТЗ с периодом и выборкой.
- **После релиза** — сравни ту же метрику до / после, с одинаковыми по длине периодами.
- **Новое приложение** — проверь, что события приходят с правильным `project` и без `environment = 'dev'` на проде, до запуска трафика.

### Готовые дашборды
- **FoxIQ — трафик по UTM:** https://ph.app-inkfolio-reader.pro/project/1/dashboard/10 — заходы, 3-й экран, email и оплаты по источникам.
- **FoxIQ — базовый пульс:** https://ph.app-inkfolio-reader.pro/project/1/dashboard/9 — заходы и логины, новые, шаги воронки, стык воронка → приложение, возвраты.

### Проверять за Claude
Claude может ошибиться: перепутать приложение, посчитать события вместо людей, взять не тот часовой пояс. Ключевые цифры перепроверяй в интерфейсе PostHog или спрашивай «откуда это?». Нашла новое правило (тестовый аккаунт, ловушку в данных) — допиши в этот файл, чтобы Claude учитывал его дальше.
