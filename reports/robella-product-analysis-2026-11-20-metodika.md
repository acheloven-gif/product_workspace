## 2. Исключение тестовых
Человек исключён целиком, если хотя бы на одном событии до верхней границы:
- `properties.is_test` или `person.properties.is_test` равно true/1;
- почта персоны или distinct_id содержит шаблон аудита: `+`, gox-media, yandex, test, example, mailinator, eevakenn, nedvedyea.
Исключено людей за весь срок: 64. Дополнительно исключаются `environment = dev`, если такое свойство появится.
**Проверка 18.11:** 5 из 34 открытий оплаты прошло по `/preview/…/main/`. Сохранённая цепочка: 18.11 16:03:52–16:24:53 МСК, полный квиз → email → 2 checkout → `funnel_purchase_fail`. Остальные 29 checkout шли по боевому `/ai-stilist-week-web/`.

По [документации FunnelFox](https://funnelfox.com/docs/editor/publishing) preview — среда для тестирования, платежи в ней работают в test mode без реального списания. Поэтому этот `funnel_purchase_fail` не является отказом живого платежа. FunnelFox также прямо указывает, что [preview-профили не должны использоваться в аналитике](https://funnelfox.com/docs/dashboard/customers). Это не живой трафик; личность проходившего тестировщиком не называем.

Исходный фильтр аудита preview не исключает. Базовые числа оставлены без изменения: 500 стартов, 38 почт, 34 открытий оплаты. Для полного исключения preview по всем шагам нужен новый запрос PostHog: сохранённых агрегатов недостаточно, чтобы определить, были ли другие preview-сессии среди стартов и почт. Без такого пересчёта боевые знаменатели не выдумываем.
