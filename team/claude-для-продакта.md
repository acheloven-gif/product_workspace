# Claude в продуктовой работе: как это устроено у Кати

Принцип: всё, что можно делать через AI, делаем через AI. Claude не «чат, где спрашиваю», а рабочее место:
он заводит задачи, читает комментарии, считает метрики, пишет ТЗ и сам ведёт журнал. Ниже, как это
собрано, и как повторить у себя за один вечер.

---

## 1. Где работать: Claude Code, не обычный чат

Обычный чат claude.ai не видит файлы и не помнит контекст между чатами. Нужен **Claude Code**:
вкладка **Code** в десктопном приложении Claude (Mac/Windows) или команда `claude` в терминале.

Отличия, ради которых всё это:
- видит и пишет файлы на твоём компьютере (журнал, отчёты, ТЗ);
- читает `CLAUDE.md` с твоими правилами в начале каждой сессии;
- помнит факты между сессиями (память привязана к папке проекта);
- подключается к ClickUp, PostHog, FunnelFox, Google Drive через коннекторы;
- несколько чатов параллельно, каждый под своё направление.

**Установка:** скачать приложение Claude, открыть вкладку Code, выбрать папку (см. п. 3).

---

## 2. Коннекторы: что подключить

Settings → Connectors в приложении Claude. Подключённые коннекторы доступны во всех чатах Code.

| Коннектор | Зачем | Примеры запросов |
|---|---|---|
| **ClickUp** | задачи, комментарии, статусы, вложения | «заведи задачу», «что нового в комментариях к задаче X», «ответь Дане в задаче» |
| **PostHog** | аналитика: события, воронки, записи сессий, SQL | «конверсия по экранам воронки за неделю», «сколько людей увидели экран ошибки» |
| **FunnelFox** | воронки: структура, экраны, транзакции | «покажи экраны воронки X», «список транзакций за вчера» |
| **Google Drive** | документы, таблицы | «найди выгрузку по чарджбэкам», «создай таблицу» |
| **Figma** | макеты | «что на экране пейволла в макете» |

Минимум для старта: **ClickUp**. Потом PostHog, когда появится свой продукт с аналитикой.

Важно про PostHog: коннектор может «тихо» переключиться на другой проект посреди сессии. Перед тем как
верить цифрам, попроси Claude проверить, в каком проекте он находится, по характерному событию.

---

## 3. Папка проекта и CLAUDE.md

Claude Code открывается в папке. В папке лежит `CLAUDE.md`: контекст, который он читает каждый раз.
У Кати это папка «Аналитика Клод» с таким `CLAUDE.md`: что за продукт, как монетизируется, какие
проекты в PostHog, какие правила анализа (только реальные данные, всегда период и размер выборки,
не смешивать веб и iOS).

Структура папки у Кати:

```
Аналитика Клод/
  CLAUDE.md          контекст: продукт, проекты, правила
  schema/            карта событий и свойств в PostHog
  playbook/          повторяемые анализы и запросы
  reports/           результаты анализов, выгрузки, отчёты
  references/        скриншоты и кадры конкурентов
  payments/          разборы по платёжке
  team/              инструкции для команды (этот файл)
```

**Как завести себе:** создай папку, например `~/Продукт/`, внутри `CLAUDE.md` с 10–15 строками:
кто ты, какой продукт ведёшь, где лежат задачи в ClickUp, какие правила. Остальное Claude
достроит по ходу, если попросить «запомни это».

Есть два уровня правил:
- `~/.claude/CLAUDE.md` — глобальный, действует во всех папках и чатах. Сюда: журнал, твой список задач, стиль общения.
- `<папка>/CLAUDE.md` — только для этой папки. Сюда: контекст конкретного продукта.

## 4. Чаты по направлениям

Один чат на одно направление, не один чат на всё. У Кати сейчас примерно так:

- **Задачи** — личный PM-чат. Сюда сваливаются все задачи как есть, голосом или текстом. Claude раскладывает их в ClickUp, в понедельник спрашивает фокус недели, в пятницу сверяет.
- **Платежи** — Stripe, Primer, чарджбэки, алерты.
- **Аналитика продукта** — по чату на продукт: Azora, Lumina, FoxIQ.
- **ТЗ и конкуренты** — разбор скринкастов, написание ТЗ.
- **Запуск продукта** — контроль первых дней после включения трафика.

Чаты живут долго, по несколько недель. Контекст внутри чата накапливается, это ценно. Новый чат
заводи под новое направление, а не под каждый вопрос.

Все чаты пишут в один журнал (п. 6), поэтому в чате «Задачи» видно, что происходило в остальных.

---

## 5. Как работать с задачами через Claude

**Заводить.** Пишешь в чат «Задачи» всё, что пришло в голову, в любом виде. Claude заводит карточки
в твоём списке ClickUp. Правила, которые он соблюдает:
- одна карточка = один результат, который можно сделать за один подход. «ТЗ по исламу и харизме» это две карточки;
- описание по шаблону: Проект / Что сделать / Результат;
- проект первым словом в названии: «Харизма: ...», «Платежи: ...»;
- перед созданием ищет дубли;
- задачи коллегам сам не создаёт, сначала предлагает.

**Изменения по задачам.** Не ходить в ClickUp руками:
- «что нового по моим задачам за сегодня» — комментарии, смены статусов;
- «прочитай комментарии к задаче X и скажи, что от меня нужно»;
- «ответь в задаче X: ...» — отвечает от твоего имени в контексте задачи;
- «закрой задачу X», «перенеси в работу», «поставь срок пятница».

**Недельный ритм.**
- Понедельник: «какой у нас план на неделю» → Claude показывает открытое, ты называешь фокус, он запоминает.
- Пятница: «что сделали, что переносим» → сверка с фокусом понедельника.
- Любой день: «что я делала вчера, коротко для дейлика».

**Статус продуктов.** Если ты говоришь Claude «запустили трафик на X», он сам двигает карточку продукта
в стадию «запуск» и заводит задачу «контроль первых дней». Факты из разговора превращаются в состояние
ClickUp без отдельной просьбы.

## 6. Рабочий журнал

Отдельная инструкция: [рабочий-журнал-инструкция.md](рабочий-журнал-инструкция.md). Коротко:
папка с файлами по датам, Claude пишет туда сам из любого чата, потом отвечает «что я делала»
и «что мы решили». Это обязательный элемент, без него чаты не знают друг о друге.

## 7. Аналитика через Claude

Когда появится продукт в PostHog:
- вопросы задаёшь словами: «конверсия с первого экрана в оплату по дням за две недели», «на каком экране воронки больше всего отваливаются», «сколько людей увидели ошибку отмены подписки»;
- Claude пишет SQL сам, показывает цифры, период и размер выборки;
- записи сессий: «найди сессии, где пользователь увидел пейволл после оплаты»;
- повторяемые отчёты складывай в `playbook/`, тогда «сделай недельный дайджест» работает одной фразой.

Правила, которые стоит вписать в `CLAUDE.md`, они спасают от ошибок:
- только реальные данные, если данных нет, сказать, а не придумать;
- всегда период и размер выборки;
- три метки на каждый вывод: **Видно в данных / Предположение / Не знаем**;
- тестовые пользователи и свои аккаунты исключать из всех метрик.

## 8. ТЗ и разбор конкурентов

Как делается ТЗ на приложение (пример: [ТЗ на приложение по исламу](https://app.clickup.com/t/1249d35f07g)):
1. Пройти воронку конкурента и само приложение, записать скринкаст. Скринкаст целиком отдать Claude, он разберёт по экранам. Скриншоты вручную не нарезать.
2. Claude собирает структуру: разделы, нижний бар, экраны, функционал каждого экрана. Формат по экранам, так удобнее разработчикам.
3. Отдельно сценарий после воронки: что пользователь видит сразу после оплаты, по шагам.
4. ТЗ в ClickUp, скринкаст и референсы приложить к задаче разработке.
5. Правило для разработчиков: сдают с доказательством самотеста (скрин, запись, события в аналитике). «Мы сделали, вы проверьте» не принимается.

Разбор веб-воронок конкурентов: пройти самой, скриншоты по экранам → Claude: «разбери воронку по шагам: что спрашивают, где пейволл, какие цены, какие триггеры». Из этого потом рождаются гипотезы.

## 9. Память: что Claude помнит сам

Claude Code запоминает факты между сессиями в папке проекта. Если он что-то понял неправильно,
скажи «запомни: ...» или «это неверно, на самом деле ...». Примеры того, что у Кати в памяти:
кто такой Даня в ClickUp, какие тестовые аккаунты исключать, что одно приложение обслуживает
много воронок, что подписка всегда покупается на вебе.

Проверить, что он помнит: «что ты помнишь про проект X».

---

## 10. Настройки, чтобы не тормозило

Claude по умолчанию спрашивает разрешение на каждое действие. В параллельных чатах это стопорит работу.
Файл `~/.claude/settings.json`:

```json
{
  "permissions": {
    "defaultMode": "acceptEdits"
  }
}
```

`acceptEdits` — файлы правит без вопросов, команды в терминале и подключения спрашивает. Для старта
достаточно. У Кати стоит `bypassPermissions`, вообще без вопросов, но это после того, как привыкнешь.

---

## Чек-лист на первый вечер

1. Установить приложение Claude, открыть вкладку Code.
2. Подключить ClickUp в Settings → Connectors.
3. Создать папку продукта с `CLAUDE.md` на 10 строк.
4. Создать `~/.claude/CLAUDE.md` по инструкции про журнал.
5. Создать `~/.claude/settings.json` с `acceptEdits`.
6. Открыть чат «Задачи», накидать всё, что в голове, попросить завести в ClickUp.
7. На следующее утро спросить «что я делала вчера» и убедиться, что журнал работает.
